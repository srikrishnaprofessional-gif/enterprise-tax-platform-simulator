# Project Overview

The **Enterprise Tax Platform Simulator** is an interactive application that demonstrates how enterprise tax systems operate in large organizations.

Many global companies rely on a complex ecosystem of systems to process financial transactions and calculate taxes correctly. These systems typically include:

* ERP systems that generate transactions
* Middleware pipelines that move data between systems
* Tax engines that determine tax amounts
* Reporting platforms that generate tax summaries
* Monitoring dashboards that detect system incidents
* AI copilots that assist analysts in understanding system operations

This project simulates these systems using **Python and Streamlit** to demonstrate the flow of enterprise tax data from transaction generation to tax reporting.

The application provides:

* ERP transaction simulation
* Middleware ETL processing
* Tax calculation engine simulation
* Tax reporting dashboards
* System monitoring
* AI copilot assistant
* Downloadable datasets

# Enterprise System Architecture

The simulator follows a typical enterprise tax system architecture.

```
ERP System
(Transaction Generation)
        ↓
Middleware Layer
(ETL / Informatica Simulation)
        ↓
Tax Engine
(Vertex Simulation)
        ↓
Tax Data Hub
(Tax Reporting)
        ↓
Monitoring + AI Copilot
```

Each module in the project corresponds to a component in this architecture.

# System Components Explained

## 1. ERP System Module

Location:

```
erp_system/transaction_generator.py
```

ERP systems record financial transactions generated by business operations.

Examples include:

* vehicle sales
* spare parts purchases
* service billing

This module simulates ERP transactions by generating datasets that include:

* transaction ID
* product type
* country
* transaction amount
* customer name

The Faker library is used to generate realistic company names.

Example simulated transaction:

```
Transaction ID: 104
Product: Vehicle
Country: US
Amount: 42000
Customer: Detroit Automotive Group
```

These transactions represent the **source data for the entire tax processing pipeline**.

---

## 2. Middleware Module (Informatica Simulation)

Location:

```
middleware/etl_pipeline.py
```

Enterprise systems rarely communicate directly with each other.

Instead, middleware tools such as **Informatica** move data between systems.

Middleware performs ETL operations:

```
Extract → Transform → Load
```

The middleware simulation performs the following steps:

1. Extract ERP transaction data
2. Validate and transform the data
3. Send the processed dataset to the tax engine

Example transformation:

```
middleware_data = transactions.copy()
middleware_data["pipeline_status"] = "Processed"
```

This step represents the **data pipeline that connects ERP systems with tax engines**.

---

## 3. Tax Engine Module (Vertex Simulation)

Location:

```
tax_engine/vertex_simulator.py
```

Tax engines calculate the correct tax amount for each financial transaction.

Common enterprise tax engines include:

* Vertex
* Avalara
* SAP Tax Service

The tax engine simulation applies tax rules based on country.

Example tax rules:

```
US        → 8% Sales Tax
Germany   → 19% VAT
India     → 18% GST
```

Tax calculation logic:

```
Tax Amount = Transaction Amount × Tax Rate
```

Example:

```
Transaction Amount: $40,000
Country: US
Tax Rate: 8%

Tax Amount: $3,200
```

This simulates how **Vertex calculates taxes in real-time during financial transactions**.

---

## 4. Tax Reporting Module (Tax Data Hub)

Location:

```
tax_reporting/tax_data_hub.py
```

After tax calculation, enterprise systems generate reports required for compliance.

Examples include:

* VAT returns
* Sales tax reports
* GST filings

The reporting module aggregates tax data by country.

Example logic:

```
report = middleware_data.groupby("country")["tax_amount"].sum()
```

Example output:

```
Country     Total Tax
US          280000
Germany     190000
India       210000
```

The results are displayed in the dashboard as charts.
